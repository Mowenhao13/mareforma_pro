# `mareforma-pro` 0.4.0 长驻 MCP 零侵入观测迭代清单

## 阶段 1：收据 Schema 升级与 `MCPProcessSupervisor` 核心骨架
- [ ] **向后兼容扩展 0.2.0 收据 Schema 与 Fail-Closed 诊断码**
  - 新增可选字段：`internal_temp_files`、`observed_egress_urls`、`observed_db_queries`
  - 新增诊断码：`concurrent_call_overlap`、`egress_proxy_bypassed`、`egress_uninspected`、`db_uninspected`、`https_path_opaque`
- [ ] **设计 `CallReceipt` 与 `SessionReceipt` 两级收据模型**
  - 单次 MCP 调用结束签发 `CallReceipt`；MCP Session 关闭或空闲超时汇总签发 `SessionReceipt`，复用现有 HMAC 验签链路
- [ ] **实现 `MCPProcessSupervisor` 进程托管与 18100 端口透明反向闸门**
  - 对外监听 Supervisor 端口 `18100`，向内拉起并托管固定监听 `18000` 的未改代码 MCP 进程，复用协议解析提取 `Mcp-Session-Id` 与 `scope_id`
- [ ] **实现确定性并发归因控制（串行闸门 / Worker 池 + 重叠降级）**
  - 默认单内部进程 `max_concurrency=1` 串行转发，支持拉起多无状态实例池扩吞吐；若关闭串行且发生并发重叠，直接标 `OPAQUE(concurrent_call_overlap)`

## 阶段 2：流式 `strace` 采集与临时文件语义分层（解决问题 1 和 4）
- [ ] **将 `strace` 采集改造为常驻 FIFO 流式消费器**
  - 启动托管进程时挂载 `strace --seccomp-bpf -f -y` 写入命名管道，后台线程实时解析并按当前激活的 `scope_id` 路由入桶
- [ ] **实现调用结束时的流式排空同步屏障（Drain Barrier）**
  - HTTP 响应返回后等待 `strace` 管道排空尾部 `openat` 事件，再封存 `CallReceipt` 并解锁槽位，防止跨请求尾部串台
- [ ] **实现临时文件“先写后读”与“未写先读”语义分层**
  - 维护每 `scope_id`/Session 的 `/tmp` 写入集合：先写后读归入 `internal_temp_files`（不误报 `OPAQUE`）；未写先读严格标 `OPAQUE(unmapped_tmpfs)`
- [ ] **在 `strace` 采集器中增加 `connect()` 外联哨兵基线**
  - 记录托管进程发起的所有外部 IP/Port 连接，为阶段 3 的代理防绕过对账和阶段 4 的未观测外联降级提供确定性依据

## 阶段 3：可选 Egress Proxy 与防绕过对账（解决问题 3）
- [ ] **实现可开关的用户态 Egress Proxy 与环境变量自动注入**
  - Supervisor 按开关启动本地代理并自动向 MCP 进程注入 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`，全程免修改服务端代码
- [ ] **支持两档 HTTPS 观测模式（免证书域名级 / 用户态临时 CA 完整 URL 级）**
  - 免证书模式经 `CONNECT` 记录域名端口并标 `https_path_opaque`；完整模式生成临时用户态 CA 经 `SSL_CERT_FILE` 等环境变量注入
- [ ] **实现 Egress Proxy 与 `strace connect()` 交叉防绕过对账**
  - 开启代理却发现直连外网 IP 标 `OPAQUE(egress_proxy_bypassed)`；关闭代理但监测到外联诚实标 `egress_uninspected`

## 阶段 4：可选 SQL/DB Hook 破解连接池盲区（解决问题 2）
- [ ] **实现语言无关的本地 TCP DB 透明转发代理（破除连接池盲区）**
  - 改写 `DATABASE_URL` / `PGHOST` / `MYSQL_HOST` 等环境变量指向本地转发端口，复用长连接池时也能按流量活跃度归因所查数据库
- [ ] **实现 Python MCP 零代码 DB 自动插桩（可选增强模式）**
  - 通过 `PYTHONPATH` + `sitecustomize.py` 自动挂接常见驱动（SQLite/Postgres/MySQL/DuckDB/Redis），穿透 TLS 与连接池采集库名与查询摘要
- [ ] **打通嵌入式数据库 `openat` 互证与未观测 DB 诚实降级**
  - 将 SQLite/DuckDB 的 `openat` 路径自动归类为本地数据库访问；未启 DB 代理/Hook 时对远端库流量标注 `db_uninspected`

## 阶段 5：黑盒靶机回归验收、OTel 导出与 0.4.0 发布
- [ ] **搭建固定 18000 端口零改代码 HTTP MCP 靶机完成 6 类回归验收**
  - 覆盖：内部 `openat` 读文件、先写后读 `/tmp`、未写先读 `/tmp`、连接池查 DB、出站 HTTPS 请求、刻意绕过代理直连外网
- [ ] **扩展 OpenTelemetry 异步导出器以呈现 0.4.0 新增证据**
  - 将 `CallReceipt` 与 `SessionReceipt` 的文件、临时文件、DB 与 URL 摘要映射为标准 Span Events 及双向 Span Link
- [ ] **封装统一 CLI 启动入口并发布 `mareforma-pro` 0.4.0**
  - 提供类似 `mareforma-pro supervise --port 18100 --internal-port 18000 [--egress-proxy] [--db-hook] -- 原命令` 的一键包装体验与迁移文档
